# Editing engines and rendered-media evidence

The existing native studio and browser editor share the director and edit decision list. Keep that boundary. The native studio has a frame renderer, a local speech worker, normalized media and an audio mix. The browser already has an offline-capable video engine and draws titles and subtitles from the same font assets. The strongest additions provide a measurable capability at one of those boundaries.

The dependency and maintenance checks below used upstream registries, licenses and repositories on November 24–25, 2026. A researched candidate has no operational status until its media output has been exercised in the intended runtime.

## Measured media

The packaged Alpine demo supplies a reproducible render and regression fixture. No creator reference/raw pair accompanied this audit, so the measurements establish technical behavior on the listed files. They do not establish professional artistic equivalence to a creator's reference. [Playable baseline](../assets/studio/sample-cut.mp4)

The measurements below use x86-64 Linux with a two-CPU quota, an 8 GiB memory limit and FFmpeg 7.1.5. Each of three serial runs counted every decoded video frame with ffprobe, then measured frame luma and scene boundaries on a width-96 limited-range YUV proxy at the original output frame rate. Normalized luma is the median frame-average Y value converted with `(Y−16)/219`. Scene times use the FFmpeg scdet threshold 8. Audio was independently decoded for integrated LUFS, true peak, maximum PCM sample amplitude and sample counts at or above full scale. The last column is the median wall time of all operations together. It is a measurement of this machine and these short clips.

The second and third rows refer to validation exports from the workspace. The packaged example has three authored scenes and yielded no hard-cut detections at the chosen threshold. Compression and gradual transitions can change what a detector sees. Report authored structure and decoded-picture evidence separately.

Run the reproducible checks with `npx vitest run src/intelligence/quality.test.ts`. They probe the packaged MP4, measure true peak on its encoded audio, and encode three short picture variants from real demo frames. A deliberately dark render triggers the picture-level check. The test applies one proposed correction and measures the decoded improvement against its target. Other cases cover missing measurements, invalid spans, cue collisions, detector confidence, decoded frame mismatches, clipping, conditional repair, issue-count limits and iteration/cost limits.

## Quality decisions exposed to the director

- Supply actual decoded dimensions, frame rate, video-stream duration and counted frames. AAC priming or padding can alter the container's duration independently of the picture.
- Compare luma in the same measured color domain. A difference greater than **0.10** on the normalized scale is a review threshold. Positive and negative differences allow a bounded trial correction. It applies only when the caller has selected that comparable grade target.
- Compare measured median shot duration against the larger of **0.35 s** or **35% of the target cadence**. Clips shorter than 1.6 target shots do not support this comparison. Differences need a story review before changing shot selection.
- Measure true peak against a configurable delivery ceiling, default **−1 dBTP** with a **0.1 dB** tolerance. Supply decoded full-scale sample spans for exact times. A scalar peak cannot localize a transient. A zero-length list means the detector scanned the output and found none.
- Authored windows support timing and canvas-fit checks. Burned-in presence, pixel contrast and measured display windows need independent picture observations. Measured contrast below **3:1** flags large text for review. If an OCR detection has reported confidence below **0.5**, it cannot confirm the expected text. Set `timingVerified` only if both display boundaries were measured.
- The repair function returns absolute brightness and gain values so subsequent passes can apply them to the original source. A trial uses at most **0.04** brightness or **3 dB** attenuation. Cumulative limits are **±0.08** brightness, **6 dB** attenuation and **three** passes. Supplying prior metrics suppresses ineffective retries. Supplying a remaining cost estimate bounds the next render. Changes to narrative, reframing, captions or effects require independent evidence.
